# Product

Everyday: a set of single screens from different consumer apps. Each screen's intended task is
in its `notes:` in mockups.yaml. [confirmed]

## Problem

People do small, everyday things on their phone between other things: pay, sign in, change a
setting, catch up, check a plan. Each should be easy, safe and accessible to complete on the one
screen it has. [confirmed]

## Users

- **Primary:** adults using their own phone, mixed experience with apps, including people who use
  large text, dark mode and screen readers. [confirmed]
- **Not for:** expert or enterprise users.

## Operating Context

Often one-handed and on the move, with interruptions. [assumption] If wrong: reach and target-size
findings would matter less.

## Key Tasks

1. **Pay for an order** (must not fail): When I've chosen my items, I want to check the total and pay,
   so I can get my order without surprises. (checkout)
2. **Log in**: When I open the app, I want to get into my account quickly, so I can continue. (login)
3. **Change a notification setting**: When notifications annoy me, I want to turn one type off,
   so I'm only interrupted for what matters. (settings)
4. **Catch up on posts**: When I have a minute, I want to scan new posts from people I follow. (feed)
5. **Check my next trip**: When travel is coming up, I want to see what's next and what I still
   need to do. (Android home)
6. **Understand what the product does**: When I first open the app, I want to know what it does
   for me and how to start. (welcome)
7. **Create an account**: When I'm new, I want to sign up and choose what I share, so I can start
   without giving away more than I mean to. (sign up, choices)

## Success Criteria

- Effectiveness: a first-time user completes each task without help.
- Efficiency: the task's main action is visible without scrolling on a standard phone.
- Satisfaction: the user knows the action worked.
